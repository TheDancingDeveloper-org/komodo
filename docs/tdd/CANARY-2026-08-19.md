## Two defects the canary caught

Both were invisible to the test suite and only surfaced against the real Core.

**1. The provider's logs were silently discarded.** Komodo Core's logger is `Targets::new().with_default(LevelFilter::OFF)` with an explicit allow-list (`km`, `core`, `periphery`, …). A crate logging under its own name emits nothing. The provider fetched and persisted 263 secrets while producing **not one visible line** — and the entire degraded-mode design rests on logging loudly. Fixed by logging under `core::infisical`, which the existing `core` entry matches by prefix, with no upstream file touched.

**2. The startup summary contradicted itself during an outage.** Startup chose its message by comparing snapshot age against the TTL. But a cold process has nothing in memory and must fall back to disk *however fresh that copy is*, so a restart during a brief outage logged two warnings about serving cached values and then finished with `Loaded secrets from Infisical` at info — the opposite of the truth. Fixed by tracking refresh success explicitly.

Neither was reachable from unit tests. Both argue for keeping the canary step in this runbook rather than trusting green tests.

## Outage test method

Infisical itself was **not** stopped. Core was pointed at a closed port (`http://127.0.0.1:1`) and force-recreated, which exercises the identical code path — refresh fails, cold process, fall back to the persisted snapshot — with zero impact on the rest of the estate. Observed:

```
WARN Restored the last-known-good Infisical snapshot from disk count=263 age_seconds=15
WARN Infisical refresh failed; serving the last known good secrets: … Connection refused
WARN Started with the last known good Infisical secrets; a live refresh did not succeed
```

and a full stack deploy succeeded in that state.

## Rollback

| Situation | Action |
|---|---|
| Provider misbehaving | `KOMODO_INFISICAL_ENABLED=false`, restart Core. Behaviour becomes identical to upstream. |
| Need the upstream image | Restore `docker-compose.yml.bak-pre-infisical-20260819`, `docker compose up -d core`. **Revert the canary stack's environment first** — upstream Core has no guard and would pass `[[infisical://…]]` through as a literal value. |

Reverting the canary needs no stored plaintext: both values are byte-identical to Infisical, so they can be re-fetched.
